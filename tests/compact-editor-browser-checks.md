# コンパクトな編集画面のブラウザー検証

ブラウザー起動を伴うため通常検証には含めない。「全てのテストを実行」または「時間のかかるテストを実行」の明示時に実施する。今回の実装では未実施。

- 有効な矢印始点で `r` を押し、相手選択・確定・取消の前後で英文の表示座標とスクロール位置が変わらないこと。同じ始点を確定するエラーでも位置が変わらず、エラーが通常案内より優先されること。
- 個別選択・境目・疑似トークン・標識自由入力・formの案内が下端に表示されること。確定・取消・別の組への移動後に古い案内が残らないこと。
- メニューの開閉で英文の位置が動かないこと。組番号はメニュー内だけに表示され、英文・訳文の見出しと常設編集ボタンがないこと。
- 操作中・ホバー中・フォーカス中に ⋯ が見えること。非操作中でもTabで到達でき、タッチ環境では常時見えること。一度に開くメニューは一つであること。
- Enter/Spaceで開き、Tab/Shift+Tabと上下矢印/Home/Endで項目へ移動できること。先頭・末尾の無効な移動項目はスキップすること。Escapeで閉じて起点へ戻り、その後は本文のショートカットを使えること。
- メニュー内で `r` や `v`、組移動のキーを押しても本文を操作しないこと。外側クリックで閉じ、クリック先の操作を妨げないこと。Tabで外へ移った場合も閉じ、フォーカスを引き戻さないこと。
- 英文・訳文の編集で対応する入力欄にフォーカスが移り、完了できること。英文変更時のリセット注意が残ること。
- 下に追加・一括追加・上へ・下へ・削除が従来どおり動き、保存とUndo/Redoが機能すること。
- 幅320px、長い英文、複数組でメニューボタンと本文が重ならず、メニューと下端案内が画面幅に収まること。長い案内は折り返し、最大高さを超える場合は内部スクロールできること。
- 通常時に下端案内の枠や予約された空白がなく、上部の共通ガイドが維持され、各組の件数表示がないこと。スクリーンリーダーで操作案内の更新とメニューボタンの開閉状態を確認できること。
