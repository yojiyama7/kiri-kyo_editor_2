# 訳文の遅延保存・デバッグJSON更新の検証

## ブラウザーで確認

- [ ] 初回表示後にversion 8の保存状態とデバッグJSONが表示される。
- [ ] 訳文入力直後はtextareaのみ更新され、表示状態JSON・保存状態JSONは直前の値のまま。操作停止後は最新の訳文へ更新される。
- [ ] 10組と50組で、それぞれ100文字を約6〜7秒間連続入力。25文字ごとに確認し、両JSON表示が連続入力中に変わらない。停止後は表示・保存状態とも最新内容に一致する。
- [ ] 50組の表示JSONは約64万文字。ブラウザーツールの長い文字列の返却上限を避け、ページ内で文字数とハッシュを計算して比較した。
- [ ] コピー時は最新の未保存訳文が表示JSONに反映され、保存状態は以前の内容のまま。訳文モードは終了せず、コピーも成功する。
- [ ] Esc、Enter、完了、英文入力への切替、Ctrl+nによる次の組への移動で最新訳文が確定する。
- [ ] 途中の自動保存をまたいだ編集でも、モード終了後のUndoで入力開始時の訳文に戻り、Redoで最終訳文に戻る。
- [ ] モード終了直後の再読み込みで最新訳文を復元する。
- [ ] 訳文モードのまま入力直後（2秒未満）に再読み込みしても、離脱時保存により最新訳文を復元する。
- [ ] 最終確認時のブラウザー警告・エラーログなし。

## 自動テスト

`editorUpdates.test.mjs` で500msと2000msの境界、連続操作による延期、文字変更を伴わない操作、IME変換中の予約取消と変換終了からの再計時、終了時保存、最新状態の取得、コピー、破棄時の取消を検証。

10組・50組を使うスケジューラーのテストでは、50ms間隔の100回の入力中にJSON生成・保存コールバックが一度も呼ばれず、停止後に各1回実行されることを確認。

- [ ] 重複書き込みが抑制され、保存失敗時に保存済み状態が進まず、同じ変更を再試行できる。

## 検証範囲の注意

- [ ] 正確な時間境界と書き込み回数は偽時計による単体テストで検証。ブラウザーの入力から実描画までの遅延を測定したものではない。
- [ ] `beforeunload` / `pagehide` が発火しないブラウザー強制終了時の未保存内容は保証しない。
