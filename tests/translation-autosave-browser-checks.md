# 訳文の遅延保存・デバッグJSON更新の検証

> 以下は旧仕様で実施したブラウザー検証の履歴。現仕様は「操作停止から500ms後に編集中の文だけをWorker内のIndexedDBへ保存し、文の切り替え時にも移動前の文を保存」。デバッグJSONは明示操作時のみ更新する。今回の変更ではブラウザー検証を再実行していない。現在の検証は `entryPersistence.test.mjs`、`persistenceStore.test.mjs`、`appPersistence.test.mjs` を参照。

2026-09-03、通常利用とは別の `127.0.0.1:5194` で実施。通常利用の保存データは操作していない。

## ブラウザーで確認

- [x] 初回表示後にv6の保存状態とデバッグJSONが表示される。
- [x] 訳文入力直後はtextareaのみ更新され、表示状態JSON・保存状態JSONは直前の値のまま。操作停止後は最新の訳文へ更新される。
- [x] 10組と50組で、それぞれ100文字を約6〜7秒間連続入力。25文字ごとに確認し、両JSON表示が連続入力中に変わらない。停止後は表示・保存状態とも最新内容に一致する。
- [x] 50組の表示JSONは約64万文字。ブラウザーツールの長い文字列の返却上限を避け、ページ内で文字数とハッシュを計算して比較した。

## 自動テスト

`editorUpdates.test.mjs` で500msと2000msの境界、連続操作による延期、文字変更を伴わない操作、IME変換中の予約取消と変換終了からの再計時、終了時保存、最新状態の取得、コピー、破棄時の取消を検証。

10組・50組を使うスケジューラーのテストでは、50ms間隔の100回の入力中にJSON生成・保存コールバックが一度も呼ばれず、停止後に各1回実行されることを確認。

`documentPersistence.test.mjs` で重複書き込み抑制、保存失敗時に保存済み状態を進めないこと、同じ変更の再試行、失敗後のモード終了時の再試行を検証。

## 検証範囲の注意

- 正確な時間境界と書き込み回数は偽時計による単体テストで検証。ブラウザーの入力から実描画までの遅延を測定したものではない。
- 実OSの日本語IME操作やブラウザーの容量超過は自動操作していない。IME中の保存抑制と保存失敗の再試行は単体テストで検証した。
- `beforeunload` / `pagehide` が発火しないブラウザー強制終了時の未保存内容は保証しない。
