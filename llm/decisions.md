# 設計判断

長期間維持すべき設計判断を、次の形式で記録する。

## 記録形式

### YYYY-MM-DD: 判断の短い名前

- 判断: 採用した方針
- 理由: その方針を選んだ理由
- 影響: 関係する機能、ファイル、または制約

## 記録済みの判断

### 2026-09-10: JSON importは事前保存後に全文書を原子的に置換する

- 判断: version 8文書のimportは現在の保存キュー完了後、Worker内の単一IndexedDBトランザクションで全文書を置換し、成功後だけ画面へ反映して1回のUndo / Redo対象にする。入力途中はimportを開始しない
- 理由: import前の保存要求による上書き、部分的な置換、ファイル選択による下書きの意図しない確定・破棄を防ぎ、失敗時に旧文書を保つため
- 影響: importは追加・マージや旧version移行を行わない。確認画面で件数を示し、同一文書では書込みと履歴追加を省略する

### 2026-09-10: JSON exportは保存完了後のIndexedDB文書を使用する

- 判断: JSON exportは開始時点までの保存可能な変更を保存キューへ送り、その完了後にWorker経由でIndexedDBを再読取してversion 8文書全体を出力する。入力途中の状態は強制確定しない
- 理由: 画面内の状態を保存済みと推測せず、実際に永続化された復元可能なデータだけを利用者へ渡すため
- 影響: export開始時点の変更世代を保存待機の境界とし、保存不能・保存失敗・読取失敗時はダウンロードしない。開始後の編集は待機対象へ追加しない

### 2026-09-06: EscでWeb UIのフォーカスを解除する

- 判断: IME変換中を除き、どの画面でもEscの既存処理が完了した後に、ボタン、入力欄、セレクト、編集可能要素などWeb UIの操作要素からフォーカスを外す。
- 理由: 取消操作後にボタンや入力欄のネイティブフォーカスだけが残り、その後のキーボード操作や表示を妨げないようにするため。
- 影響: `src/App.svelte` のグローバルkeydown捕捉と `src/focusRelease.ts`。既存のEscによる取消・確定・ダイアログ終了を先に処理するため、フォーカス解除は次のタスクへ遅延する。

### 2026-09-06: 文書形式を外側のversion 8へ一本化する

- 判断: 文書はWeb Worker内のIndexedDBを正本とし、外側の `EntryDocument.version: 8` だけで形式を識別する。各組の文書にはversionを持たせない。version 8以外の文書と旧復旧ジャーナルは自動破棄して初期サンプルへ戻し、version 8として識別できる不正データは保持して手動破棄を求める。
- 理由: 文書全体と組内に別のバージョンが併存する矛盾をなくし、旧形式と現行形式の破損に対する扱いを明確に分けるため。
- 影響: IndexedDBのメタデータはversion 8。復旧ジャーナル自体はversion 2、キーバインド設定はversion 1を維持し、復旧ジャーナルには `documentVersion: 8` を記録する。旧形式の自動破棄後は閉じられる警告を表示する。

### 2026-09-06: 基礎下線の内部表示を一時状態にする

- 判断: `Group.kind` は内容から決まる永続分類だけを保存し、基礎下線を内部編集のために開いた状態は組IDの集合としてメモリ内だけに持つ。開閉は履歴・保存へ含めず、標識・構造の編集確定時にだけ内容に基づく再分類を同じ編集へ含める。
- 理由: 永続的な構造分類と一時的な操作状態が同じ `kind` を書き換えていたため、移動だけで保存やUndoが発生し、再読み込み時の扱いも複雑になっていたため。
- 影響: 組内移動では内部を出ると閉じ、実際の組移動、Undo / Redo、再読み込み、保存データ破棄では全て閉じる。T/D分割中の基礎下線は開かない。レイアウト計算時だけ開いた基礎下線を複合下線として扱う。

### 2026-09-05: キーバインド設定のモード略号と絞り込み

- 判断: キーバインド設定内のモードは、`N` / `V` / `VM` / `A` / `B` / `F` / `I` / `T` / `PI` / `MI` / `MS` / `D` / `M` の重複しない1〜2文字バッジで表示する。フィルタは単一モード選択とし、そのモードを利用できる操作を表示する。
- 理由: 多数の適用モードを省スペースで識別しつつ、特定のモードで使える操作をすぐ探せるようにするため。
- 影響: 略号はモードの日本語説明とともに共通定義し、一覧・詳細ヘルプ・競合表示で共通利用する。フィルタ横の説明ボタンから全モードの詳細をモーダル表示する。フィルタは表示だけに作用し、優先順位の番号、編集中の設定、競合検査、保存形式を変えない。

### 2026-09-06: T化・D分割に伴う有向矢印の終点を左へ追従させる

- 判断: 有向矢印の終点スロットをT化またはD分割した場合は終点を左スロットへ付け替え、分割解除時は左スロットへの終点を元の親スロットへ戻す。同格の解除時削除は従来どおりとする。
- 理由: T化・D分割の作成と解除で、矢印が指す実際のスロットを対称に維持するため。
- 影響: T化・D分割と解除時の矢印参照、Undo / Redo、自動保存、矢印描画。

### 2026-09-05: 訳文の表示と編集で同じ要素を維持する

- 判断: 訳文は常設のtextareaをreadonlyで切り替え、同じ文字組みの非表示ミラーで高さを確保する。編集枠はoutlineで描画し、余白・幅・フォントは両状態で共通にする。
- 理由: 表示と編集で文字の開始位置・折り返しが変わることを防ぎ、入力欄を内容に必要な高さに保つため。
- 影響: 訳文欄のフォーカスはマウント時だけでなく編集状態の変更時にも移す。ミラーには末尾改行の高さを維持するゼロ幅スペースを付け、支援技術からは隠す。
- 完了ボタン: 枠内右下に1行と同じ高さで配置する。編集時だけミラー末尾にボタン幅と間隔を確保する不可分のinline-blockを置き、収まらない場合は予約領域だけを次の行へ送る。本文の折り返し幅を狭めず、文字配置を維持する。

### 2026-09-04: プラン完了時にコミットする

- 判断: プランに基づく作業を完了したら、その作業に属する変更だけをGitコミットしてからユーザーへターンを返す。
- 理由: 完了した作業を明確な単位で履歴に残し、次の作業を安全に開始できる状態にするため。
- 影響: リポジトリ内で行うプラン実行全般。既存の変更や無関係な変更はコミットに含めない。

### 2026-09-04: D分割の非対称比率を保存する

- 判断: 複数の論理要素を持つ下線のD分割はカーソル直後の境界を使い、非対称な場合は `SlotSplit.ratio` に左側の比率を保存する。省略は従来の1:1とする。この比率は論理範囲のみを復元し、表示幅には使わない。表示は1:1を基準に左右それぞれの標識・formの必要幅を確保し、片側の必要幅が全体の半分を超える場合だけその側を広げる。D全体は元の単語・下線幅と左右必要幅の和の大きい方にして元領域と中央を揃える。
- 理由: 左右の境界を幅変更や再読み込みから独立させ、既存保存データとも互換性を保つため。
- 影響: D分割の論理範囲、表示領域、標識・form幅計測、保存検証。T分割と単一要素のD分割は論理上1:1のままだが、Dの表示幅は左右の必要幅により非対称になりうる。

### 2026-09-04: 同格表示と `+` 標識を分離する

- 判断: 同格接続線の表示は「同格」とし、`+` は `n` / `S` / `O` / `nC` と同様に同格の開始側・相手側へ設定できる標識として扱う。
- 理由: 接続種別を示す表示文字と、接続可能な端点標識は別の意味を持つため。
- 影響: 同格の作成・保存検証・標識変更時の整理・操作案内・接続線描画。

### 2026-09-05: 編集本文を操作案内で移動させない

- 判断: 各組の低頻度操作は右上の重ね表示メニューに集約し、英文・訳文の見出しと操作行を常設しない。組番号はメニュー内に表示する。モード案内は操作中の組だけ画面下端に固定表示し、専用の縦幅を予約しない。
- 理由: 選択中に本文の位置が動くことを防ぎ、常設操作欄や説明用の空白による視覚的な負担を減らすため。
- 影響: 各組の操作メニュー、英文・訳文の表示、モード案内と関連エラー。メニューは文ブロックの右上に32px四方で重ね、本文側に縦長の専用余白を確保しない。操作中・ホバー・フォーカス時に表示し、タッチ環境では常時表示する。保存形式と既存ショートカットは維持する。


### 2026-09-05: キーバインドの固定完全順序と定型標識入力

- 判断: 全操作に固定の完全順序を与え、取消、移動、Undo/Redo、モード内操作、標識・form、開始・構造変更の順で選ぶ。同分類は操作IDの文字コード順、UndoはRedoより先。競合は警告するが保存を許可する。
- 理由: 任意の異なる2操作の優先関係を常に決定し、設定の登録順やハンドラーの配置に依存させないため。
- 影響: `src/keybindings.ts` がモード別候補生成・遷移・順位・警告を共通管理する。Appは組移動を先決めせず、EntryEditorが定型標識の入力状態を含めて解決した同じ結果を使う。対象がない操作でも下位候補へフォールバックしない。
- 定型標識: Normal の明示的な開始操作（初期値 `m`）で空バッファの `MARKER_SEQUENCE` に入れる。従来のNormalからの先頭文字入力も維持し、同モードでは標識の先頭文字・続き・取消・移動だけを候補にする。不成立の打鍵は入力を確定後、Normal で一度だけ再判定する。これにより初期設定の `aux` を入力でき、途中のUndo・標識削除は候補にならない。`s` と `sad` の接頭辞関係は競合ではなく、入力途中と移動、および同一文字列の異なる標識は競合とする。
- 保存: 通常操作は最大3件、取消は固定Escと追加3件まで。文書と独立したバージョン付きlocalStorageへ保存し、保存成功後だけ有効設定を切り替える。読込失敗時は元データを保持して初期値で動作する。
- 設定画面: 操作名、丸いヘルプボタン、常設の3入力欄を同じ行の共通グリッドに置き、全操作でスロットの列位置を揃える。ヘルプはホバー・フォーカスで要約、クリックで機能・モード・例・現在値を表示する。空欄を保存せず左詰めする。固定Escは欄に表示せず、取消操作では固定Escとは別に3件まで登録できる。入力欄のEscはその割り当てを解除する。入力待ちのスロットは、クリック後から単発キーの取得完了または連続文字列欄のフォーカス終了まで強調表示する。単発キーの取得完了時は入力欄からフォーカスを外し、同じ欄を直後にクリックして再入力できるようにする。モバイルでは一覧だけを縦スクロール領域にせず、見出し・説明・モードフィルタ・表ヘッダーを含むダイアログ全体を縦スクロールさせる。表の横スクロールは維持する。
- 内部固定操作: ダイアログのフォーカス移動は `Tab` / `Shift+Tab` に固定して設定画面から隠す。操作処理にはキーを直書きせず、`src/inputConfig.ts` の既定キーと固定対象IDを使う。固定対象IDから外せば既定値付きで設定画面へ復帰し、保存済みの上書き値は適用・保存時に固定値へ正規化する。
